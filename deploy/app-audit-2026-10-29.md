# MamaLead 1.4.18 application audit

Scope: test the current desktop app, repair regressions and push the latest app and
website source. Server deployment and installer/feed publication remain deferred.
The proposed new Decision Maker search flow is not part of this change.

## Repairs

- Website Lookup previously displayed **Scan stopped** when every selected website
  had finished but one returned an error. It now displays **Scan complete with
  errors**. An interrupted, incomplete scan still displays **Scan stopped**.
- Email Finder's old **High confidence** dropdown option fell through to All, while
  **Needs verify** selected businesses without email. The dropdown now offers
  explicit Valid, Invalid, Risky, Unknown and Not checked filters alongside All,
  Has email, Pending and No website. Filters respect the typed saved search.
- Updated legacy test fixtures to reflect one main email per company, owner-role
  evidence and licence gating. Tests use temporary profiles and simulated access;
  no production licence or customer records were modified.

## Verification

The 19 core suites in `scripts/verify-release-audit.cjs` cover database operations,
existing owner discovery/evidence, contact crawling, main-email selection, social
deduplication, Maps limits, branded exports, update configuration, billing and Assist.
The database suite passes 98 assertions after its fixtures were updated.

The 11 desktop suites cover:

- All 11 pages with empty and populated data, in light and dark themes.
- Actual Electron IPC, SQLite storage, local billing/AI fixtures, licence gates,
  activation/revocation, restart persistence and scoped email verification.
- Saved search by name/domain/handle/email/phone; clearing restores results.
- A 2,000-lead workspace: paging, old-record search and complete exports.
- Maps 20/25/40 limits, fewer available results, live current-run results, saved
  searches, and PDF/Excel exports of a selected run, including more than 1,000 rows.
- Native CSV import and pasted inputs of 13, 31 and 100 sites, duplicate/invalid
  handling, cleared drafts, and accurate 15/50-business Decision Maker counts.
- Email validity filters, current-import scope, progress, Stop/resume and source
  labels; Website Lookup selection, partial failures, retries, scrolling and exports.
- Notification card click/keyboard/read/unread/delete behavior and persistence.
- Assist page links, including Reports, without automatically starting actions.

Additional Phone Finder fixture checks verified main-number ranking, local versus
international duplicates, stale website-number cleanup, retained manual/Maps
numbers, and PDF/Excel output. A deliberately stalled contact page returned the
homepage number in about 3.6 seconds; Stop cancelled the request.

Website verification covers eight module galleries, 23 current light-mode sample
screenshots, 33 FAQs, original logos, download links, aligned pricing actions and
1440/768/390-pixel layouts. No renderer or missing-asset errors were detected.

## Reproduction and limits

Build first, then run:

```powershell
npm run build
node scripts/verify-release-audit.cjs core
node scripts/verify-release-audit.cjs desktop
node scripts/verify-website-current.cjs
```

The website check expects the local website preview on port 8798. Audit logs and
screenshots are local verification artifacts and are not shipped in the app.

External services are exercised through controlled fixtures. This audit does not
claim that every public website exposes an owner email, that a real mailbox will
accept mail, or that third-party services can never fail. Existing Decision Maker
behavior was regression-tested; its search strategy was deliberately unchanged.
